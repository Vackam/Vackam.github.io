왜 만들었는가?

AI가 잘되니까 자동 추리 게임을 만들고 싶었다. 근데 추리 심문을 유저가 직접하는.

추리 게임의 가장 큰 문제가 뭘까?

추리의 재미다. 엄청난 게임 시스템이 있더라도 추리의 내용이 재미없으면 안된다. 생각할 것도 없이 단순히 "아니꼬와서 죽였어요"하면 열심히 푼 사람이 바보 되는 거다.

그리고 추리까지 가는 과정이 아주 중요하다. 레포데마냥 좀비 나오는 곳으로만 가면 답이 나와선 안된다. 추리게임에선 아무도 그것을 원하지 않는다.

그럼 저 두 문제점만 해결하면 되는데,

1번은 본인이 극작가도 아니고 평범한 공대생이기 때문에 해결하기 어렵다. AI에게 생성을 맡기도록 하고.

2번이 핵심인데 여태까지 안되었던 AI를 통해 직접 심문(물론 지금은 너무 많다)을 도입함으로 정답으로 가는 길에 유저가 재미를 느낄 수 있도록 했다.

여기에 각 잡고 하는 것이 아닌 대학생이 쉬는 시간에 잠깐씩 하는 거를 목표로 했다.

그래서 결론으로

매일 시나리오가 나오면서 유저가 직접 심문하는 추리 게임!

이 매추리이다.

랭그래프 도입

랭그래프를 도입하기 전까지 모든 호출은 단순 API 호출이었다. 이렇게 하니 시나리오 생성과 용의자 자체 정보 생성(할루시네이션 대처)에서 어려움을 겪었고 이를 대처하기 위해 랭그래프를 도입했다.

시나리오 생성

함수 하나가 모든 단계의 생성하는 함수를 알고 있어서 이것을 하나하나 호출했어야 했다. 이를 랭그래프를 도입해 각 단계를 그래프의 노드와 엣지로 만들어서 관리를 용이하게 했다.

할루시네이션 대처

도구 호출을 가능하게 해서, 복잡한 if/else 등으로 처리하지 않고 자신이 정보 생성 함수 호출을 할 수 있도록 했다.

llm 진입점이 단일화 되었고, 단계별로 관리를 할 수 있어서 좋다.

AI를 코드 활용 뿐 아니라 실제 프로젝트에 녹여본 첫 프로젝트 였다.

AI가 응답을 잘 할 수 있도록 few shot, one shot 등 다양한 기법을 적용해 볼 수 있는 기회였다.

또한, API 호출을 억제하기 위해서 핑거프린트 등을 도입하면서 보안에 대해서도 공부할 수 있었다. 특히, AI Server를 우리 백엔드만 호출할 수 있는 구조를 만듦으로 안정성을 가져간 것이 기억에 남는다.

WebGL이 굉장히 어려운 것을 알아냈다. 괜히 엔진을 쓰는 게 아닌가보다.
